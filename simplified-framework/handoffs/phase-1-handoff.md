## 4. Per-task breakdown

### Task 1 — `episode-planner.md` → `showrunner.md`

**Spec sources in `todo-v4.md`:** §Task 1, §Agent Roles → Showrunner.

**Steps**
1. `git mv simplified-framework/pipeline/agents/episode-planner.md simplified-framework/pipeline/agents/showrunner.md`
2. Rewrite the prompt content. Key behavioral changes from `todo-v4.md`:
   - Keep the existing writer barrier (the showrunner does not write dialogue, does not choreograph scenes turn by turn, does not decide teachable moments inside a finished draft).
   - **Delete `flaws[]` (and its child `amplification` field)** from the output shape of `episode-plan.yaml`. The showrunner does not author a flaw inventory in v4. Do not edit validators or schemas in this batch; just stop authoring the field.
   - Make the projection more prose-forward and less choreographic. Treat `scene_design` as obligation-shaping, not beat-scripting.
   - Use `narrative_synopsis` and `character_beats` to encourage private stakes, offscreen life, and non-mystery life where they strengthen the episode.
   - The plan stays focused on storyline design rather than flaw inventory.
   - Encode the story problem through situation design, interpersonal pressure, and episode obligations — never through direct flaw-taxonomy language or explicit quiz-planning instructions.
3. Add authoring guidance for `showrunner-projection.yaml` as a derived brief for `staff_writer` — but do **not** implement the projection-writing behavior or the resumability fields. Those belong to `create_transcript` in batch 2. In Phase 1 the prompt should document that the showrunner eventually produces this projection, without coupling to command-flow details not yet in place.
4. Do not instruct the showrunner to read `reference/flaw-taxonomy.yaml` during planning. In v4 the showrunner is not flaw-aware.

**Input sources the showrunner reads:** `stories/{story_id}/story.yaml` (now carries student-facing `premise` and showrunner-facing `episodes[].summary` per Phase 0), plus prior episodes' plans or artifacts if continuity requires it.

### Task 2 — `screenwriter.md` → `staff-writer.md`

**Spec sources in `todo-v4.md`:** §Task 2, §Agent Roles → Staff writer.

**Steps**
1. `git mv simplified-framework/pipeline/agents/screenwriter.md simplified-framework/pipeline/agents/staff-writer.md`
2. Rename the role uniformly from `screenwriter` to `staff_writer` inside the prompt.
3. Rewrite the prompt. Key behavioral notes from `todo-v4.md`:
   - Keep the current writer barrier and story-first stance.
   - Add stronger emphasis on breathing turns, subtext, private stakes, and offscreen life as story-enriching guidance — not as mandatory beat quotas.
   - Discourage episodes that rely only on civic-register stakes when private stakes would make the story stronger.
   - Let the writer draft continuous story flow first rather than writing to app-shaped scenes. The raw draft is a flat ordered `turns` list without scene structuring.
   - The writer does **not** read `reference/flaw-taxonomy.yaml` and does not optimize for quiz coverage.
   - The writer assigns stable pre-structuring `turn_id`s using the existing transcript-validator `tNN` format (at least two digits, globally unique within the episode). Order is list position; never compute chronology from the numeric tail.
4. The writer outputs `transcript.raw.yaml` with minimum shape: `story_id`, `episode_id`, `title`, `characters`, `turns` (flat ordered list; each turn has `turn_id`, `speaker`, `text`), `revision_history`, and `status`. In Phase 1 document this as the writer's target; the command-level orchestration that actually invokes the writer with these fields lives in `create_transcript.md` (batch 2). The agent prompt should be ready for that wiring without prescribing the orchestration steps itself.
5. Do **not** introduce scene segmentation, scene summaries, or `scenes[]`. Those come from the later `transcript-structurer` (batch 2).

### Task 3 — `flaw_injector.md` → `script-doctor.md`, remove `flaw-reviewer.md`

**Spec sources in `todo-v4.md`:** §Task 3, §Agent Roles → Script doctor.

**Steps**
1. `git mv simplified-framework/pipeline/agents/flaw_injector.md simplified-framework/pipeline/agents/script-doctor.md`
2. `git rm simplified-framework/pipeline/agents/flaw-reviewer.md`
3. Rewrite the script-doctor prompt. Key behavioral changes:
   - Change the role from direct reviser to proposer-analyst.
   - Reads the **operator-approved** raw draft first (`transcript.raw.yaml`), not an unreviewed story draft.
   - Produces a candidate set of flaw-carrying turns — not a fixed-count episode template.
   - Suggests flaw labels drawn from `reference/flaw-taxonomy.yaml` canonical IDs, plus an `expression_strength` of `strongly_expressed` or `moderately_expressed` per candidate. **There is no `unmistakable | showcased | heightened` amplification vocabulary in v4.** If the prompt references the old vocabulary, remove it.
   - Returns **up to 5 candidates by default** in the first proposal set. The operator can request more via chat.
   - Prefers the smallest viable edit. Proposal types are `tweak`, `replace`, and `add_beat`. There is no `keep` proposal type — an unproposed candidate is kept only if the operator places it in `approved_anchors[]`.
   - For `add_beat`, the new turn receives a fresh unused `tNN`-format `turn_id` (numerically larger than any existing id is the safe default); never renumber existing ids.
   - For `add_beat`, the proposal must include exactly one placement key: `insert_after_turn_id` or `insert_before_turn_id`.
   - After operator approval, the script doctor applies only the latest approved proposal set and writes `transcript.post-doctor.yaml`.
   - The script doctor does **not** silently rewrite the story, does not apply changes without operator approval, does not manufacture flaws in characters who should remain corrective, and does not act as a second hidden approver.
4. Document the output shape for `flaw-proposals.yaml` per `todo-v4.md` §Raw-draft and proposal-file shape. Key fields: `candidate_turns[]`, `proposals[]`, `approved_anchors[]`, `recommended_turn_ids[]`, `revision_history[]`, plus `story_id`, `episode_id`, `source_draft`, `status`. The command-level orchestration of `status` transitions belongs in `create_transcript.md` (batch 2) and does not need to be in the script-doctor prompt itself.
5. Remove any v3 language about flaw review, scene-distinctness requirements, fixed-count targets, or amplification bands.
