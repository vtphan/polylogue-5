# Simplified Instructional Model

The framework is designed around a short, deterministic teaching loop.

## Student Goal

Students should be able to:

1. notice a weak or incomplete reasoning move
2. understand why it is weak
3. recognize the same move again in a later turn

## Runtime Shape

The intended runtime flow is:

1. read the episode
2. complete one modeled warm-up
3. complete one guided warm-up
4. complete 3 to 5 challenge levels
5. leave with one final takeaway

## Content Rule

Each episode should primarily teach one flaw. Supporting flaws are allowed, but the package should still feel like one main lesson rather than a taxonomy survey.

## Feedback Rule

Feedback should be short, explicit, and tied to the turn. The package should not rely on the app to infer explanations from hidden metadata.
