# Simplified Conceptual Model

The simplified Lens framework uses one core conceptual layer:

- `reasoning flaws`

This replaces the older multi-layer student-facing model built around lens, facet, and explanatory variables.

## Core Idea

A discussion contains moments where someone's reasoning is weak, incomplete, or misleading.

Each teachable moment should be tagged with one primary reasoning flaw.

The job of the app is to help students:

- notice that flaw
- understand why it matters
- recognize it again later

## Starter Flaw Set

The current starter set is:

- jumping to a conclusion
- not enough evidence
- ignoring another perspective
- trusting a source too quickly
- missing important conditions or consequences

These are student-facing categories.

They should be written and taught in plain language.

## Hidden Complexity

The simplified framework does not need a second required conceptual layer.

If richer metadata is kept for authoring or analytics, it should remain optional and hidden.

That means:

- no required explanatory layer in the runtime contract
- no need to diagnose underlying force for each flaw
- no need to expose bias or group-dynamics language in the first version

## Episode Design Implication

Each episode should be designed around:

- one primary reasoning flaw
- one optional secondary reasoning flaw
- several clear instances of the primary flaw

This keeps the learning target clear and repeated.
